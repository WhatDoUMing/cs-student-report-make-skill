# SQL 实验报告排版规范（实测记录）

本文件记录 `sql_report_make` 的排版规范、**为什么这样定**、以及踩过的坑。
改配置或改生成器前建议先读一遍。

## 〇、母本的用途（容易误解）

`template` 指向的 `<序号>_command.docx`（工作区根目录下的指导书，如 `1_command.docx`、`2_command.docx`）**只用来取页面设置（纸张与页边距）和样式**：
脚本 `Document(template)` 之后会清空它的段落与表格，再按 Markdown 重建内容。
报告的 6 列表格、五个栏目、嵌套数据表都由 Markdown 生成，
**不是**往母本那张表里填单元格——文档里别再写成“用母本表格”。

## 一、行距：整篇只用三种固定值

原报告（转换工具产出）**完全没有设置行距**：`document.xml` 里没有 `w:line`，
样式里只有 `Normal` 的 `w:spacing w:after="200"`、`Compact` 的 `before/after=36`。
于是正文行距由字体默认行高决定，代码块又是另一种字号，看起来时松时紧。

现在统一为（报告表内容格里也按这三档）：

| 内容 | 行距 | 段前 | 段后 | 字号 |
| --- | --- | --- | --- | --- |
| 报告标题（`#`） | 固定 18 磅 | 0 | 10 磅 | 16 磅 加粗 居中 |
| 一级标题（`##`，`<form>` 之外的章节） | 固定 18 磅 | 10 磅 | 6 磅 | 14 磅 加粗 |
| 二级标题（`###`） | 固定 18 磅 | 8 磅 | 4 磅 | 12 磅 加粗 |
| 正文 / 列表 / 引用 | 固定 18 磅 | 0 | 0 | 12 磅，首行缩进 2 字符 |
| 代码 / 命令输出 | 固定 12 磅 | 0 | 0 | 9 磅 Consolas |
| 报告表里的栏目名 | 固定 14 磅 | 0 | 0 | 12 磅 加粗（黑体） |
| 报告表里的正文与表格 | 固定 14 磅 | 0 | 0 | 10.5 磅；表头 10.5 磅加粗 |

对应 XML：18 磅 = `w:line="360" w:lineRule="exact"`；14 磅 = `w:line="280"`；
12 磅 = `w:line="240"`。全篇只有这三种。

### 为什么必须做两件事

1. **固定行距**：倍数行距（`lineRule="auto"`）随字体行高浮动，正文与代码交界处会跳变。
2. **关闭文档网格**：Word 新文档默认带 `docGrid`，会把行高吸附到网格倍数。
   每个段落加 `<w:snapToGrid w:val="0"/>`，并把 `sectPr` 的 `docGrid` 改成 `type="default"`。

### 代码块为什么要“一行一段落”

原报告把一个代码块塞进**一个段落**（段落里有多个 `w:br` 换行）。这样行距无法按行控制，
而且长行折行后缩进会漂移。改成“一行一个段落”后：

- 每行都能统一行距；
- 空行用零宽空格 `\u200b` 占位，不会被 WPS 丢段；
- 代价是段落数变多（实验1 报告约 480 段），文件略大，但排版稳定。

## 二、全文黑色（三处一起改）

原报告的 `source code` 样式带着一整套语法高亮配色：

```
4F81BD 335B8A 366091 007020 902000 40A070 880000 4070A0
BB6688 60A0B0 BA2121 06287E 19177C 666666 BC7A00 7D9029 FF0000
```

只改正文 run 是不够的——样式和主题里的颜色随时会被引用。所以：

1. **正文 run**：每个 run 显式 `color=000000`；
2. **样式定义**：遍历 `doc.styles`，把能拿到的 `<w:color>` 全部改 `000000`；
3. **主题配色**：`word/theme/theme1.xml` 里所有 `<a:srgbClr val="...">`（含 accent1~6、
   hyperlink、followedHyperlink）改成 `000000`。

### 自检该看哪里

Word 内置的样式表（`styles.xml` 里的 `latentStyles`，以及未使用的 `Table Grid` 表格样式）
**本身就带颜色定义**（`FFFFFF`、`1F497D` 等），它们不参与渲染。所以自检只统计：

- `document.xml` 里的 `<w:color>`；
- 文档**实际用到**的样式定义里的 `<w:color>`；
- 所有 run 的 `font.color.rgb`。

实验1 报告的自检结果：`正文颜色 {'000000': 769}`、`实际 run 颜色 {'000000': 769}`、
`使用样式中的非黑颜色 无`。

## 三、报告表（母本尾部的 6 列表格）

学校母本尾部有一张 6 列的报告表，本次把**报告正文整体装进这张表**：

| 行 | 内容 | 处理 |
| --- | --- | --- |
| 第 1 行 | `实验报告` | 6 列合并（`gridSpan=6`），黑体加粗居中 |
| 第 2 行 | 题目 / 姓名 / 学号 | 键居中、值左对齐（`<form>` 的 `<row>` 按 3 对一组） |
| 第 3 行 | 日期 / 实验环境 / 实验数据 | 同上 |
| 第 4 行 | 栏目内容 | 6 列合并；栏目名照母本报告表抄（实验一：`1．实验目的：`、`实验内容和要求：`、`实验重点和难点：`、`实验程序：`、`实验总结：`；实验二只有 4 个：`1．实验目的：`、`实验内容：`、`实验程序：`、`实验总结：`） |

- 栏目名用黑体 12 磅加粗，内容段落 10.5 磅、固定行距 14 磅。
- 内容里的**数据表渲染成嵌套表格**（`cell.add_table`）：S 表 6×4、P 表 7×4、J 表 8×3、
  SPJ 表 20×4、错误对照表 5×3、脚本清单表 13×3，都带 Table Grid 边框。
- 代码块写在内容格里，逐行着色（本作业全部黑色）、固定行距 12 磅。
- 注意：python-docx 统计 `Document.paragraphs`/`tables` **不含表格内的内容**，
  校验时要递归遍历单元格，否则会误判“表格数=1、段落数=2”。

## 四、目录与页码（本作业关闭）

- 本作业按用户要求**不要目录页**：`toc.enabled=false`，既不生成目录表，也不写标题书签。
- 需要目录时把它打开：每个标题段落插入书签 `_H1`、`_H2`…；
  目录表右列插入 `PAGEREF <书签名> \h` 域（`fldChar begin` + `instrText` + 结果占位 + `end`）；
  目录表生成后被移到正文最前面。首次打开若页码显示为占位值，按 `Ctrl+A` 再 `F9` 更新域。
- **书签 id 必须用确定性序号**：早期版本用 `abs(hash(name)) % 100000`，
  而 Python 的字符串 hash 每个进程都加盐，导致同样输入生成两份不同 docx。现已改为序号。

## 五、代码来源与长行

- `fence_to_sql` 按**正文代码块出现顺序**（0 起）把代码块替换为 `SQL/*.sql` 的内容，
  这样报告里的代码与真正执行的脚本一字不差（脚本里的注释也一并进报告，
  正好满足“每行代码或一段代码后面要有注释”的要求）。
  报告表内容格里的代码块同样参与这个编号。
  - ⚠ 编号是**全文字面顺序**，改一次 Markdown（增删表格、拆合代码块）就会整体错位：
    本次把 S 表里的 P 表、J 表拆成独立表格后，配置没跟着改，结果任务3 显示成 `ALTER TABLE`、
    任务7 显示成错误演示脚本、任务2 的“运行结果（表结构）”被 INSERT 语句顶掉，
    而「命中 x/y」照样报满。**必须逐个代码块核对内容**。
  - `SQL/*.sql` 开头不写 `/* ==== 实验1 数据库定义实验 / 任务N：… ==== */` 这类横幅批注
    （`agent.md` RULE 1：不要写入批注内容），只保留 `--` 逐行说明注释。
- 文本区宽约 415 磅，9 磅 Consolas 一行约能放 76 个半角字符。
  超过就会折行；固定行距下**折行内容仍完整显示**（不会被裁切），
  只是紧一些。实验1 报告里有 10 行超宽（最长 140 字符，是 `SHOW CREATE DATABASE` 的输出框）。
  若某张输出框必须完整显示为一行，把该块字号调到 6 磅左右可容纳约 115 字符，
  更长的输出建议改用“关键行摘录”。

## 六、验证方法

1. 用 python-docx 回读，**递归**统计 run 颜色、段落行距分布、嵌套表格数与目录域数量；
2. 校验 `word/theme/theme1.xml` 与 `styles.xml` 中**实际使用样式**的颜色；
3. 逐块确认代码块与 `SQL/*.sql` 内容一致（比对行数与首末行）；
4. 解压所有 XML 做一次 `ElementTree.fromstring` 解析，确认文档结构合法；
5. **连跑两遍生成器**，比对 `word/document.xml` 的 sha256，确认输出可重复。

## 七、环境与编码

- Python 3 + `python-docx`；
- Markdown 里的中文、全角引号、`` ` `` 反引号都按普通字符处理；
- 脚本入口 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`，
  否则在 GBK 控制台打印中文会抛 `UnicodeEncodeError`；
- 覆盖已有报告前先备份（如 `_备份-原实验报告.docx`）。

## When to Use

需要写/改**数据库（SQL）上机实验报告**，且满足任一情况时使用：

- 工作区里有实验指导书母本 `<序号>_command.docx`（如 `1_command.docx`、`2_command.docx`），
  该次实验的序号文件夹（如 `1\`、`2\`）里有 `实验报告.md`（报告内容）、`SQL/`（脚本）和 `config-exp<序号>.json`（生成配置）；
- 用户抱怨报告「行距不一致/太挤」「颜色太多」「代码块花花绿绿」；
- 要把 SQL 源脚本（带注释）整理进报告。

### 工作区结构（每次实验一个序号文件夹）

```
<工作区>\
├─ agent.md                         项目约定（可选）
├─ sql_report_make\                 本技能（装好后长期不变）
├─ 1_command.docx                   实验一指导书（含报告表母本，只取页面设置与样式）
├─ 2_command.docx                   实验二指导书
├─ 1\                              实验一产物：SQL\、实验报告.md、实验报告.docx、config-exp1.json
└─ 2\                              实验二产物：SQL\、实验报告.md、实验报告.docx、config-exp2.json
```

## 设计取舍：为什么不「往母本表格里填空」

| 做法 | 问题 |
| --- | --- |
| 用 Word/脚本往母本表格单元格里逐格填字 | 单元格是固定尺寸，段落一多就撑破、分页错乱；行距、颜色、表格嵌套全要手工调 |
| **本技能：Markdown 描述内容 + 生成器排版**（母本只取纸张/页边距/样式） | 报告结构由 Markdown 决定，排版规则集中在一处；改内容只改 `.md`，重新生成即可 |

因此 `template` 指向的 `<序号>_command.docx` **只用来取页面设置与样式**——不要把“用母本”理解成“往母本的表格里填”。

## 三步走

1. **准备内容**：写 `<序号>\实验报告.md`。正文列在 `<form>` 块里，栏目名照母本报告表的原样写（实验一 5 个；实验二 4 个，没有「实验重点和难点」）：

   ```markdown
   # 实验报告

   <form>
   <title>实验报告</title>
   <row>题目 | 实验1  数据库定义实验 | 姓名 | 张三 | 学号 | 2025001</row>
   <row>日期 | 2026-10-08 | 实验环境 | ... | 实验数据 | ...</row>

   <section name="1．实验目的：">
   ...
   </section>

   <section name="实验内容和要求：">
   ...
   </section>

   <section name="实验重点和难点："> ... </section>
   <section name="实验程序："> ... </section>
   <section name="实验总结："> ... </section>
   </form>

   ## 附：实验脚本清单
   | 文件 | 对应任务 | 说明 |
   ...
   ```

   栏目里可以放段落、**加粗**、`等宽`、有序/无序列表、表格、```sql 代码块与 ``` 结果块——
   这些都会按规范渲染进报告表的那一格。

2. **写配置**：把 `examples/demo/config-example.json` 复制成 `<序号>\config-exp<序号>.json`，
   改 `template`（指向 `<序号>_command.docx`）、`markdown`、`out`、`sql_files`、`fence_to_sql`：
   - `template`/`markdown`/`out` 的相对路径按**配置文件所在目录**解析；
   - `sql_files` 的相对路径按 **`markdown` 所在目录**解析（写 `SQL\01_create_database.sql` 即同文件夹下的脚本），也可全用绝对路径。
3. **生成并自检**：`python scripts/make_sql_report.py <配置.json>`，再打开 docx 确认报告表内容与代码块。

## 六条固定约定（本技能的默认值，均可按需改配置）

1. **不要目录页**：`"toc": {"enabled": false}`。目录表与 `PAGEREF` 域都不生成，标题也不写书签。
2. **全角空格换成双空格**：`"space_fix": true` 时，报告表标题行、信息行、正文、表格、代码块里的
   `U+3000`（以及 markdown 里字面写的 `\u3000`）统一换成两个半角空格。
3. **主体格式用母本尾部那张 6 列报告表**：`<form>` 块渲染成
   「实验报告」标题行（6 列合并）+ 信息行（题目/姓名/学号/日期/实验环境/实验数据）+
   内容行（6 列合并，依次是 `1．实验目的：` → `实验内容和要求：` → `实验重点和难点：` →
   `实验程序：` → `实验总结：`，以上是实验一母本；实验二母本只有 `1．实验目的：`/`实验内容：`/
   `实验程序：`/`实验总结：` 四个栏目）。数据表、错误对照表、脚本清单表作为**嵌套表格**放进内容格。
4. **全文黑色**：`highlight` 里所有颜色填 `000000`，并且正文 run、样式定义、主题配色
   **三处一起改**——只改正文 run，Word 里还会冒出蓝/红/绿的语法高亮。
5. **统一行距**：正文 18 磅、代码 12 磅、报告表与表格 14 磅，全部 `exact` 固定值并关闭文档网格。
6. **代码块引用真实脚本**：`fence_to_sql` 按**全文代码块出现顺序**（0 起，**含报告表内部的代码块**）
   换成 `SQL/*.sql` 内容；生成器会打印「命中 x/y」，未命中会提示编号不对。
   ⚠ **脚本里不写横幅批注**：`SQL/*.sql` 开头不要再放
   `/* ==== 实验1 数据库定义实验 / 任务N：… ==== */` 这类装饰性注释块，
   只保留 `--` 形式的逐行说明注释，正好满足“每行代码或一段代码后面要有注释”的要求。

## 排版规范（实测可用）

| 内容 | 行距（固定值，`exact`） | 段前/段后 | 字号 | 颜色 |
| --- | --- | --- | --- | --- |
| 报告标题（`#`） | 18 磅（360 twips） | 0 / 10 磅 | 16 磅 加粗 居中 | 黑 |
| 一级标题（`##`） | 18 磅 | 10 / 6 磅 | 14 磅 加粗 | 黑 |
| 二级标题（`###`） | 18 磅 | 8 / 4 磅 | 12 磅 加粗 | 黑 |
| 正文、列表、引用 | 18 磅 | 0 / 0 | 12 磅，首行缩进 2 字符 | 黑 |
| 报告表栏目名 | 14 磅（280 twips） | 0 / 0 | 12 磅 加粗（黑体） | 黑 |
| 报告表内容、表格单元格 | 14 磅 | 0 / 0 | 10.5 磅 | 黑 |
| 代码块、命令输出 | 12 磅（240 twips） | 0 / 0 | 9 磅 Consolas | 黑 |

全篇**只有三种行距取值**（360 / 240 / 280 twips，即 18 / 12 / 14 磅），都是 `w:lineRule="exact"` 固定值；
并且每个段落都关闭“对齐到文档网格”（`snapToGrid=0`），文档网格设为 `default`——否则 Word 会按网格重排行高，出现行距忽大忽小。

## 统一黑色的做法（关键）

`source code` 这类样式自带语法高亮配色（`1F497D`、`9E3A38`、`F2730A`…），必须三处一起处理：

1. **正文 run**：所有 run 显式设置 `color = 000000`；
2. **样式定义**：遍历 `doc.styles`，把样式里的 `<w:color>` 全部改成 `000000`；
3. **主题配色**：`word/theme/theme1.xml` 里的 `<a:srgbClr val="...">` 全部改成 `000000`，
   否则主题强调色一旦被样式引用就会带颜色。

自检时只统计 **document.xml 的颜色**与**文档实际用到样式的颜色**：Word 内置的
`latentStyles` 和未使用的表格样式里本身带有颜色定义，它们不参与渲染。

## 已知坑

1. **空行占位**：代码块的纯空行要写成零宽空格 `\u200b`，纯空格段落会被 WPS 保存时丢掉。
2. **长行折行**：宽度超过文本区（约 415 磅）的代码行会折行，固定行距下折行仍然显示完整（不会被裁），只是紧一些。
3. **目录页码**（仅当打开目录时）：用 `PAGEREF` 域引用标题书签。首次打开如果显示的是占位 `1`，按 `Ctrl+A` 再按 `F9` 更新域即显示真实页码。
4. **表格替换代码块**：`fence_to_sql` 的键是**全文代码块出现顺序**（从 0 开始数，**含 `<form>` 内部**）。
   ⚠ 顺序会随 Markdown 编辑整体错位：曾把某张表里的子表拆成独立表格后代码块数量变了，
   而配置没跟着改，结果**任务3 显示成 `ALTER TABLE`、任务7 显示成错误演示脚本、
   任务2 的“运行结果（表结构）”被 INSERT 语句顶掉**——命中数照样是满分。
   所以**改完 `实验报告.md` 必须重新数一遍编号，并逐个代码块打开 docx 核对内容**。
5. **Markdown 解析范围**：段落、有序/无序列表、引用、表格、代码块、分隔线、`<form>` 块；
   报告表内容格里**同样支持表格**（渲染成嵌套小表）与 `---` 分隔线（渲染成段落下边框），
   但**不支持再嵌套 `<form>` 或图片**。
6. **行内标记**：正文段落做**去标记**处理（`**加粗**`、`` `代码` ``、链接文字保留）；
   报告表内容格里**保留** `**加粗**` 与 `` `等宽` ``。
   ⚠ 实现顺序必须是「先 `parse_inline()` 拆段，再对每段 `normalize()`」；
   反过来先 normalize 会把 `**` 和 `` ` `` 删掉，导致表格里的加粗/等宽全部丢失（这是修过的 bug）。
7. **母本的用途**：`template` 指向的 `<序号>_command.docx` **只用来取页面设置（纸张与页边距）与样式**，
   报告结构、6 列表格与栏目都由 Markdown 生成；不要把“用母本”理解成“往母本的表格里填”。
8. **中文与编码**：源程序/脚本文件名可能含中文与全角括号；脚本入口 `sys.stdout.reconfigure(encoding="utf-8")`，否则 GBK 控制台打印中文会报 `UnicodeEncodeError`。
9. **不要覆盖用户手改**：重新生成前先备份（如 `_备份-原实验报告.docx`）。**docx 是生成物**，改内容要改 `实验报告.md`。
10. **生成必须可重复**：书签 id 等标识要用确定性序号，**不要用 `hash()`**（Python 字符串 hash 每次进程都不同，
    会导致同一次输入生成两份不同的 docx）。改完生成器后跑两遍比对 `word/document.xml` 的 sha256。
11. **从 docx 反推 Markdown 会丢东西**：Word 分不清“1 个还是 2 个空格”，合并单元格、嵌套表格、跨页空段落很难还原；
    万不得已才反推，并且要逐节核对（曾反推时丢过“附：实验脚本清单”表，需要手工补回）。

## 校验清单

- [ ] 自检输出「全文黑色、行距统一为三档固定值」
- [ ] `document.xml` 颜色只有 `000000`；实际 run 颜色只有 `000000`
- [ ] 行距只有 3 种取值，且都是 `exact`：360（正文/标题）、280（报告表）、240（代码）
- [ ] 没有目录（`PAGEREF` 数与书签数都为 0，除非配置里打开）
- [ ] 全角空格 `U+3000` 次数为 0（已换成双空格）
- [ ] 报告表存在：4 行 × 6 列，标题行与内容行做了 6 列合并（`gridSpan=6`）
- [ ] 内容行栏目齐全：1．实验目的：/ 实验内容和要求：/ 实验重点和难点：/ 实验程序：/ 实验总结：
- [ ] 嵌套表格齐全（以实验一为例：S 表 6×4、P 表 7×4、J 表 8×3、SPJ 表 20×4、错误表 5×3、脚本清单表 13×3）
- [ ] 代码块里没有 `/* ==== 实验1 数据库定义实验 / 任务N：… ==== */` 这类横幅批注
- [ ] `fence_to_sql` 每个编号都指向**对应任务**的脚本（逐块打开 docx 核对，不能只看命中数）
- [ ] `fence_to_sql` 命中数与配置条数一致，且每个 `SQL/*.sql` 的行都能在报告里找到
- [ ] 报告表里的 `**加粗**` 与 `` `等宽` `` 生效（产物里能数到加粗 run）
- [ ] 页面设置与母本一致（`page_width/height`、四边页边距）
- [ ] 连跑两遍，`word/document.xml` 的 sha256 完全相同（可重复生成）
